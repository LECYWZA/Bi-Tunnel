# Bi-Tunnel 移动端 App 技术方案（简化版）

## 需求范围

- **仅实现隧道 + 混合代理**（SOCKS5/HTTP 本地代理）
- **不需要**系统代理（VpnService / NEPacketTunnelProvider）
- **不需要** TUN 虚拟网卡
- Android/iOS 双端保活

---

## 一、整体架构

```
+---------------------------------------------------+
|               Flutter UI 层                        |
|  服务器配置 / 连接管理 / 日志展示 / 状态指示        |
+--------------------+------------------------------+
                     | MethodChannel (状态/命令)
+--------------------v------------------------------+
|           原生隧道服务层 (Native)                   |
|  - 启动本地 SOCKS5/HTTP 代理监听 (127.0.0.1:1080) |
|  - 管理与服务端的隧道长连接 (WebSocket/TCP)         |
|  - 转发本地请求 ←→ 隧道                            |
|  - 双端后台保活                                    |
+--------------------+------------------------------+
```

### 核心设计原则

- **数据不经过 Dart isolate**：原生层直接处理网络 I/O，MethodChannel 只传状态和命令
- **隧道协议复用服务端**：兼容现有 Node.js 服务端的 WebSocket/TCP 隧道
- **客户端只做代理转发**：本地监听 `127.0.0.1:1080`，接收的流量通过隧道发往服务端

---

## 二、关键简化点（相比原方案）

| 原方案 | 现方案 | 原因 |
|--------|--------|------|
| Go/Rust 隧道核心引擎 | 原生层 (Kotlin/Swift) 直接实现隧道客户端 | 纯代理场景不需要高性能转发引擎 |
| Cgo/FFI 桥接 | 不需要 | Kotlin/Swift + Network.framework 完全胜任 |
| gomobile / flutter_rust_bridge | 不需要 | 减少工具链依赖和编译复杂度 |

## 三、Android 实现

### 启动流程

```
Flutter 点击"连接"
  → MethodChannel 调用 Kotlin 原生
  → Kotlin 启动 Foreground Service (常驻通知栏)
  → Service 内建立 WebSocket/TCP 隧道连接到服务端
  → 连接成功后启动本地 SOCKS5/HTTP 代理 ServerSocket
  → 通知 Flutter 连接状态
```

### 保活

- **Foreground Service** + `START_STICKY`
- 常驻通知栏（低优先级，可折叠）
- 引导用户加入电池优化白名单
- 监听网络变化自动重连（`CONNECTIVITY_ACTION` / `NetworkCallback`）

## 四、iOS 实现

### 启动流程

```
Flutter 点击"连接"
  → MethodChannel 调用 Swift 原生
  → Swift 启动音频后台会话
  → 建立 WebSocket/TCP 隧道连接 (URLSessionWebSocketTask / NWConnection)
  → 启动本地 SOCKS5/HTTP 代理 listener
  → 更新 Flutter 状态
```

### 保活：静默音频循环

在 `Info.plist` 声明 `UIBackgroundModes: audio`：

```xml
<key>UIBackgroundModes</key>
<array>
    <string>audio</string>
</array>
```

实现要点：

1. App 切后台时，Swift 层 `AVAudioPlayer` 循环播放一段极短的静音音频文件（如 0.1 秒静音 MP3，无限循环）
2. 监听 `AVAudioSessionInterruptionNotification`，在电话/闹钟等中断结束后自动恢复播放
3. 音频会话类别设为 `.playback`（混音模式，不影响其他 App 音乐）

> 自签场景下无审核限制，此方案可稳定工作。如需上架 App Store 则需备选为退后台断连+前台重连。

## 五、CI/CD：GitHub Actions 多版本构建

**能。** 矩阵构建一键打出所有版本：

```yaml
name: Build Mobile App

on:
  push:
    tags:
      - 'v*'

jobs:
  build-android:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        arch: [arm64-v8a, armeabi-v7a, x86_64]
    steps:
      - uses: actions/checkout@v4
      - uses: subosito/flutter-action@v2
        with:
          flutter-version: '3.x'
          channel: 'stable'
      - run: flutter build apk --split-per-abi --target-platform android-${{ matrix.arch }}

  build-ios:
    runs-on: macos-latest
    steps:
      - uses: actions/checkout@v4
      - uses: subosito/flutter-action@v2
        with:
          flutter-version: '3.x'
          channel: 'stable'
      - run: flutter build ipa --no-codesign
```

GitHub Actions 支持：

| 平台 | Runner | 产物 |
|------|--------|------|
| Android arm64-v8a | ubuntu-latest | app-arm64-v8a-release.apk |
| Android armeabi-v7a | ubuntu-latest | app-armeabi-v7a-release.apk |
| Android x86_64 | ubuntu-latest | app-x86_64-release.apk |
| Android 全架构 AAB | ubuntu-latest | app-release.aab |
| iOS 真机 | macos-latest | Runner.ipa |

### 版本管理

- 打 `git tag v1.2.3+4`（版本号 + 构建号）→ Actions 自动触发
- Flutter 自动读取标签中的版本号
- 产物自动上传到 GitHub Releases
- 可手动触发工作流选择构建特定版本
