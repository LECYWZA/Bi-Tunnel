# Bi-Tunnel 移动端 App（B方案：非 VPN 后台常驻模式）技术实现与环境搭建文档

本文档针对 **Bi-Tunnel 移动端 App（B方案：非 VPN 后台服务模式）** 编写，详细阐述架构设计、双端常驻保活原理、JWT 认证流程以及所需开发/构建环境支撑。

---

## 一、 方案概述（B方案）

**B方案核心理念**：放弃系统级 VPN (`VpnService` / `NEPacketTunnelProvider`) 模式，改为**纯本地代理与隧道客户端**模式。

### 为什么选择 B 方案？
1. **解决 VPN 冲突问题**：手机系统同时只能运行一个系统级 VPN。采用 B 方案**不会占用系统 VPN 标记位**，完全可以与手机上正在运行的第三方 VPN（如公司内网 VPN、其他代理软件）同时兼容运行。
2. **轻量高效**：App 仅需在本地监听代理端口（如 `127.0.0.1:1080` SOCKS5/HTTP）或建立 TCP/UDP/WebSocket 隧道长连接。

---

## 二、 整体技术架构

采用 **Flutter (UI & 业务逻辑) + 跨平台 Core (Go/Rust) + 双端原生保活 (Kotlin / Swift)** 的三层架构：

```
+-------------------------------------------------------------+
|                 UI 层 (Flutter 3.x)                         |
|  - JWT 登录认证 / 身份 Token 硬件级安全存储                |
|  - 节点配置拉取、连接状态展示、日志与设置                    |
+------------------------------+------------------------------+
                               | Native MethodChannel
+------------------------------v------------------------------+
|                 双端原生保活与后台服务层                     |
|  - Android: Kotlin Foreground Service (前台服务 + 通知栏)   |
|  - iOS: Swift Silent Audio / Location Keep-Alive            |
+------------------------------+------------------------------+
                               | C / Cgo / JNI 桥接
+------------------------------v------------------------------+
|                 隧道核心引擎 (Go / Rust)                     |
|  - 编译为 Android .so 动态库                                 |
|  - 编译为 iOS .xcframework 静态库                           |
+-------------------------------------------------------------+
```

## 三、 双端后台常驻保活实现原理

由于不占用系统 VPN，切后台后需要防止操作系统（尤其是 iOS）将应用进程冻结。

### 1. 安卓端（Android）保活策略
* **前台服务 (Foreground Service)**：启动一个带有常驻状态栏通知的服务（如：“Bi-Tunnel 后台服务运行中”），使系统将其视为主级活跃进程。
* **电池优化白名单**：引导用户授予“忽略电池优化”及“允许后台自启”权限。
* **进程守护与拉起**：Service 标记为 `START_STICKY`，若被强杀会自动重新触发创建。

### 2. 苹果端（iOS）保活策略
* **无声音频循环保活 (Silent Audio Loop)**：
  1. 在 iOS `Info.plist` 中配置 `UIBackgroundModes` 包含 `audio`。
  2. 当 App 切到后台时，通过 Swift 原生 `AVAudioPlayer` 循环播放一段完全静音的微型 MP3/AAC 音频文件。
  3. **中断恢复机制**：监听 `AVAudioSessionInterruptionNotification`，在受到系统电话或音视频中断结束后，自动恢复静音播放，保证 TCP/WebSocket 隧道 Socket 长连接不中断。

## 四、 JWT 身份认证与安全存储

1. **登录交互**：用户在 Flutter 界面输入账号密码 -> 调用后端 API (`/api/v1/auth/login`) 换取 JWT Token。
2. **硬件级安全存储**：
   * 使用 `flutter_secure_storage` 插件。
   * Android 端存储于 **Android Keystore** 加密区。
   * iOS 端存储于 **iOS Keychain** 安全区。
3. **HTTP 自动续签拦截器**：
   * 所有后端 API 请求由 Dio/HttpClient 统一拦截，自动在 Header 中添加 `Authorization: Bearer <JWT_TOKEN>`。
   * 当收到 `401 Unauthorized` 响应时，发起 Refresh Token 无感刷新。

## 五、 环境支撑与开发配置说明（解答“是否需要安装环境”）

> [!IMPORTANT]
> **结论**：**需要安装对应的环境支撑！**
> Flutter 只是一个 UI 与跨平台逻辑框架，要将应用打包编译为真实运行在手机上的 APK (Android) 或 IPA (iOS) 文件，以及编译 Go/Rust 底层隧道 Core，**必须在开发机上安装配置对应的 SDK 与编译工具链**。

### 1. 核心支撑环境清单

| 环境名称 | 必要性 | 作用与用途 |
| :--- | :--- | :--- |
| **Flutter SDK** | **必选** | 编译 Flutter/Dart 代码、运行 Flutter 命令、管理 App 依赖包。 |
| **Java JDK (JDK 17)** | **安卓必选** | Android Gradle 构建工具必须运行在 Java 虚拟机上。 |
| **Android Studio & SDK** | **安卓必选** | 提供 Android SDK Build-Tools、Platform-Tools、NDK（编译 C/C++/.so 库所需）。 |
| **macOS & Xcode** | **苹果必选** | **iOS 端打包必须依赖 macOS 系统与 Xcode 工具链**（Windows 无法直接编译 iOS 的 IPA 包）。 |
| **CocoaPods** | **苹果必选** | iOS 原生 Pod 依赖包管理工具。 |
| **Go 语言环境 (Go 1.21+)** | **Core 必选** | 将底层隧道 Core 交叉编译为 `.so` (Android) 和 `.xcframework` (iOS)。 |

---

### 2. 环境搭建步骤与配置指南

#### (A) 安装 Flutter SDK
1. 下载 Flutter SDK (推荐 3.19+ / 稳定版)。
2. 解压并将 `flutter/bin` 路径添加到系统 PATH 环境变量中。
3. 在终端运行环境诊断命令：
   ```bash
   flutter doctor
   ```
   该命令会自动检查当前系统缺少的 SDK 和工具链。

#### (B) 安卓构建环境配置 (Windows / macOS 均可)
1. 安装 **Android Studio**。
2. 在 Android Studio 的 SDK Manager 中勾选并安装：
   * `Android SDK Platform` (如 Android 14 / API 34)
   * `Android SDK Build-Tools`
   * `Android NDK (Side by side)` (用于编译 `.so` C 库)
   * `Android SDK Command-line Tools`
3. 配置环境变量 `ANDROID_HOME` 指向 Android SDK 目录。

#### (C) 苹果构建环境配置 (必须在 macOS 上)
1. 在 Mac App Store 安装 **Xcode**。
2. 安装 Xcode Command Line Tools：
   ```bash
   xcode-select --install
   ```
3. 通过 Homebrew 安装 CocoaPods：
   ```bash
   brew install cocoapods
   ```

#### (D) 隧道 Core 编译环境配置
1. 安装 Go 语言包。
2. 安装 Go Mobile 交叉编译工具：
   ```bash
   go install golang.org/x/mobile/cmd/gomobile@latest
   gomobile init
   ```
3. 编译命令示例：
   * 编译 Android 动态库：
     ```bash
     gomobile bind -target=android -o android/app/libs/bitunnel.aar ./src/core
     ```
   * 编译 iOS 静态框架：
     ```bash
     gomobile bind -target=ios -o ios/Runner/BiTunnelCore.xcframework ./src/core
     ```

### 3. 全平台（iOS / Android / Windows / Linux）云端 CI/CD 构建方案

**答案是：完全可以！而且这是最优雅、最现代化的开发模式！**

借助 **GitHub Actions 矩阵构建 (Matrix Build)**，你只需要在 Windows 本地写代码并执行 `git push`，云端的 GitHub 服务器就会**同时在 Linux、macOS、Windows 三个平台上自动并行编译**，一键生成所有平台的二进制产物！

#### 全平台云端编译分工一览

| 目标平台 | 云端构建 Runner | 产物格式 | 说明 |
| :--- | :--- | :--- | :--- |
| **Android** | `ubuntu-latest` | `.apk` / `.aab` | 自动配置 JDK、Android SDK & NDK，编译二进制 |
| **iOS** | `macos-latest` | `.ipa` / `.xcarchive` | 自动配置 Xcode、`gomobile` 框架并导出签名/未签名包 |
| **Windows** | `windows-latest` | `.exe` / `.zip` | 自动编译 Flutter Windows 桌面端可执行程序 |
| **Linux** | `ubuntu-latest` | `.deb` / `.AppImage` | 自动编译 Linux 桌面端程序包 |

#### GitHub Actions 工作流模板示例 (`.github/workflows/build.yml`)

```yaml
name: Cross-Platform Auto Build

on:
  push:
    tags:
      - 'v*' # 每次打 Tag (如 v1.0.0) 自动触发全平台打包

jobs:
  build-mobile-and-desktop:
    name: Build for ${{ matrix.target }}
    runs-on: ${{ matrix.os }}
    strategy:
      matrix:
        include:
          - target: android
            os: ubuntu-latest
            cmd: flutter build apk --release
          - target: ios
            os: macos-latest
            cmd: flutter build ipa --no-codesign
          - target: windows
            os: windows-latest
            cmd: flutter build windows
          - target: linux
            os: ubuntu-latest
            cmd: flutter build linux

    steps:
      - name: Checkout Code
        uses: actions/checkout@v4

      - name: Setup Java (for Android)
        if: matrix.target == 'android'
        uses: actions/setup-java@v3
        with:
          distribution: 'zulu'
          java-version: '17'

      - name: Setup Go (for Tunnel Core)
        uses: actions/setup-go@v4
        with:
          go-version: '1.21'

      - name: Setup Flutter
        uses: subosito/flutter-action@v2
        with:
          flutter-version: '3.19.x'
          channel: 'stable'

      - name: Build Target
        run: ${{ matrix.cmd }}

      - name: Upload Artifacts
        uses: actions/upload-artifact@v4
        with:
          name: release-${{ matrix.target }}
          path: build/
```
